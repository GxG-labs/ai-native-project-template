# Структура проекта

Эта карта — единственный источник назначения папок.

```text
PROJECT.md               ← зачем существует проект
RULES.md                 ← правила работы агентов

intent/                  ← что и зачем делаем: цели, brief, задачи

context/
  sources/<topic>/       ← сохранённые raw-материалы по теме

ai/
  context.md             ← устойчивые факты о проекте
  methods/               ← playbook и способы подхода к работе
  skills/                ← повторяемые исполнимые процедуры
  workflows/             ← последовательности шагов и циклы
  checklists/            ← (по необходимости) критерии проверки

tenants/                 ← (по необходимости) tenant-specific материалы
  <tenant>/
    raw/                  ← сырые материалы
    curated/              ← вручную подготовленные канонические материалы
    config/               ← готовый runtime-пакет tenant для новых запусков

runs/                    ← (по необходимости) execution history
  <tenant>/<run-id>/
    config/               ← неизменяемая копия tenant config
    input/                ← вход конкретного запуска
    output/               ← результаты
    logs/                 ← технические записи

output/
  drafts/                ← промежуточная работа
  final/                 ← принятые результаты

workbench/input/         ← неразобранные файлы текущей задачи
```

Создавайте по необходимости:

```text
data/                    ← структурированные данные
docs/
  gauntlet/<scope>/      ← target, current, gaps, changes одного контура
  decisions/             ← устойчивые решения, ADR-*.md
src/                     ← исходный код
scripts/                 ← утилиты
tests/                   ← автоматические проверки
evals/                   ← проверка AI-поведения и артефактов
templates/               ← заготовки повторяемых артефактов
tmp/                     ← одноразовая локальная работа
```

## Два контура

### Компиляция знаний

```text
context/sources/<topic>/ → ai/methods/<topic>.md → ai/skills/<topic>/SKILL.md
raw material                 playbook                skill
```

Skill создаётся только если playbook описывает повторяемую процедуру.

### Gauntlet Loop

```text
docs/gauntlet/<scope>/
├── target.md   ← желаемое состояние; для разработки ПО — целевая архитектура
├── current.md  ← факты о состоянии сейчас
├── gaps.md     ← разрывы, следующий шаг и проверка
└── changes.md  ← журнал проверенных изменений системы
```

`target.md` — единственный владелец желаемого состояния. Не создавайте
отдельный документ «desired state». Каждая задача меняет систему, закрывает
или уточняет gap и оставляет проверяемую запись в `changes.md`.

## Правила роста

- Не создавайте структуру заранее.
- Добавляйте подкаталог, когда плоский список уже мешает ориентироваться.
- Добавляйте `README.md` как навигационный шлюз, когда имя папки и её
  непосредственные файлы не позволяют быстро понять назначение, границы и
  необходимость читать глубже. В нём укажите назначение папки, что в неё
  входит и не входит, карту детей, правило чтения и ссылки на владельцев.
  README ссылается на правила и состояние, но не копирует их.
- Для растущих реестров опишите scope, поля и по одному правильному и
  неправильному примеру.
