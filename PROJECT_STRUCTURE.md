# Структура проекта

Эта карта — единственный источник назначения папок.

```text
PROJECT.md               ← зачем существует проект
RULES.md                 ← правила работы агентов

intent/                  ← что и зачем делаем: цели, brief, задачи

context/
  sources/<topic>/       ← сохранённые raw-материалы по теме

ai/
  context.md             ← устойчивые факты о проекте
  methods/               ← playbook и способы подхода к работе
  skills/                ← повторяемые исполнимые процедуры
  workflows/             ← последовательности шагов и циклы
  checklists/            ← (по необходимости) критерии проверки

tenants/                 ← (по необходимости) tenant-specific материалы
  <tenant>/
    raw/                  ← сырые материалы
    curated/              ← вручную подготовленные канонические материалы
    config/               ← готовый runtime-пакет tenant для новых запусков

runs/                    ← (по необходимости) execution history
  <tenant>/<run-id>/
    config/               ← неизменяемая копия tenant config
    input/                ← вход конкретного запуска
    output/               ← результаты
    logs/                 ← технические записи

output/
  drafts/                ← промежуточная работа
  final/                 ← принятые результаты

workbench/input/         ← неразобранные файлы текущей задачи
```

Создавайте по необходимости:

```text
data/                    ← структурированные данные
docs/
  spec/<scope>/          ← требования и целевая архитектура по модулям
    spec.md              ← вход и карта модульной спецификации
    <module>/            ← (по необходимости) детали модуля
  plan/<change>/         ← план реализации по модулям
    plan.md              ← вход и порядок реализации
    <module>/            ← (по необходимости) детали изменения модуля
  gauntlet/<scope>/      ← gaps и журнал проверенных изменений
  decisions/             ← устойчивые решения, ADR-*.md
src/                     ← исходный код
scripts/                 ← утилиты
tests/                   ← автоматические проверки
evals/                   ← проверка AI-поведения и артефактов
templates/               ← заготовки повторяемых артефактов
tmp/                     ← одноразовая локальная работа
```

## Основные контуры

### Изменение ПО

```text
intent/<change>/intent.md → docs/spec/<scope>/spec.md → docs/plan/<change>/plan.md
          зачем                    что строим                  как меняем
                                                                  ↓
                                                          код + тесты + diff
                                                        фактическая реализация
```

`intent.md` фиксирует проблему, результат и ограничения. `spec.md` —
принятые требования и целевую архитектуру. `plan.md` нужен только для
нетривиального или рискованного изменения и называет файлы, порядок работы,
риски и проверку. Для небольшой задачи достаточно одного файла по
`templates/intent.md`.

`spec.md` и `plan.md` служат входами в свои папки. Когда одного файла уже
недостаточно, они дают карту модульных подпапок и ссылки на детали. Не
создавайте модульную структуру заранее.

Текущую реализацию не пересказывают в отдельной папке: её владельцы — код,
конфигурация, тесты и история git. Документы ссылаются на них как на
доказательства, а не создают второй источник правды.

### Компиляция знаний

```text
context/sources/<topic>/ → ai/methods/<topic>.md → ai/skills/<topic>/SKILL.md
raw material                 playbook                skill
```

Skill создаётся только если playbook описывает повторяемую процедуру.

### Gauntlet Loop

```text
docs/spec/<scope>/spec.md        ← желаемое состояние и целевая архитектура
docs/gauntlet/<scope>/gaps.md    ← разрывы, доказательства и следующий шаг
docs/gauntlet/<scope>/changes.md ← журнал проверенных изменений системы
```

Дерево `docs/spec/<scope>/` — единственный владелец желаемого состояния;
`spec.md` служит его входом и картой. Фактическое состояние подтверждается
ссылками на код, тесты, конфигурацию или метрики внутри `gaps.md`; отдельный
документ current state не создаётся. Каждая задача меняет систему, закрывает
или уточняет gap и оставляет проверяемую запись в `changes.md`.

## Правила роста

- Не создавайте структуру заранее.
- Добавляйте подкаталог, когда плоский список уже мешает ориентироваться.
- Добавляйте `README.md` как навигационный шлюз, когда имя папки и её
  непосредственные файлы не позволяют быстро понять назначение, границы и
  необходимость читать глубже. В нём укажите назначение папки, что в неё
  входит и не входит, карту детей, правило чтения и ссылки на владельцев.
  README ссылается на правила и состояние, но не копирует их.
- Для растущих реестров опишите scope, поля и по одному правильному и
  неправильному примеру.
