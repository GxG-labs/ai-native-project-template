# План автономной разработки

Набор плагинов, инструментов и процессов для автономной разработки на Python и TypeScript с GitHub (тариф Free). Названия и версии сверяйте перед установкой: они меняются быстро.

---

## 1. Плагины Claude Code

### Методика и дисциплина работы
- **Superpowers** (`superpowers@claude-plugins-official`): сначала спецификация и план, затем разработка через тесты. Снижает риск, что агент уйдёт не туда.
- **hookify**: правила поведения через markdown-файлы, например «не трогать `main`», «не удалять миграции».

### Git и Pull Request
- **commit-commands**: коммит, коммит с push и открытием PR одной командой, очистка локальных веток, удалённых на сервере.
- **GitHub** (официальная интеграция): issues, PR, поиск по репозиторию.
- **pr-review**: автоматическое ревью PR, замечания в понятной форме.

### Автономный режим
- **ralph-loop**: агент продолжает работу, пока не выполнены критерии готовности.
  - Работает только тогда, когда есть тесты, по которым видно, что задача завершена.
  - Обязательно ставьте лимит итераций, иначе он может быстро израсходовать квоту.

## 2. Инструменты проверки

| Задача | Python | TypeScript |
|---|---|---|
| Модульные тесты | pytest | Vitest |
| Браузерные тесты | pytest-playwright | Playwright |
| Линтинг и форматирование | ruff | ESLint, Prettier |
| Проверка типов | mypy | `tsc --noEmit` |

- Браузерные тесты агент пишет и запускает сам.
- Для ручной проверки в браузере используйте встроенный браузер Claude или Claude in Chrome.
- Для desktop-приложений используйте computer use.

---

## 3. Защитные механизмы

- **Pre-commit хуки** (pre-commit для Python или Husky для TypeScript): линтеры и проверка типов до каждого коммита.
- **CLAUDE.md** в корне репозитория с правилами работы:
  - работать только в feature-ветке;
  - не пушить в `main`;
  - не менять конфиги CI без явного разрешения;
  - после каждой задачи писать отчёт простыми словами.
- **Токен GitHub** только для одного репозитория и только с нужными правами.
- **Лимиты**: максимум итераций в ralph-loop, бюджет токенов, контроль минут GitHub Actions.

---

## 4. CI на GitHub Actions

- Запуск на каждый PR: линтеры, проверка типов, модульные и браузерные тесты.
- Тариф Free даёт 2 000 минут в месяц для приватного репозитория.
  - Держите тесты быстрыми.
  - Полный набор браузерных тестов запускайте реже, например перед слиянием.
- **claude-code-action** можно использовать для автоматического ревью в CI. Учитывайте, что он расходует токены при каждом запуске.

---

## 5. Цикл работы

1. Вы описываете задачу и приёмочные критерии простыми фразами.
2. Superpowers формирует спецификацию, вы её подтверждаете.
3. Агент пишет тесты по сценариям, затем код.
4. Pre-commit и CI прогоняют проверки.
5. Браузерный тест проходит сценарии из списка.
6. Агент открывает PR с отчётом простыми словами: что изменилось и что проверить вручную.
7. Вы подтверждаете, и изменения попадают в `main`.

---

## 6. Ограничения

- Агент, который пишет код и сам его проверяет, может пропустить собственные ошибки. Сценарии проверки задавайте заранее.
- Для критичных частей (безопасность, платежи, персональные данные) попросите разработчика посмотреть результат.
- Зелёные тесты не означают отсутствие багов. Они означают, что проверено то, что вы описали.
- На бесплатном тарифе для приватных репозиториев нет защиты веток. Правило «не пушить в `main`» держится на CLAUDE.md и на токене.
