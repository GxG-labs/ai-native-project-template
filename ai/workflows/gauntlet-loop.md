# Gauntlet Loop

Gauntlet Loop применяется к системе, которую нужно приблизить к целевому
состоянию: коду, контентному процессу, исследовательскому контуру или
операционной процедуре.

## Запись состояния

Для одного контура создайте `docs/gauntlet/<scope>/` по шаблонам из
`templates/gauntlet-loop/`.

`target.md` — единственный источник желаемого состояния. Для разработки ПО в нём
описывается целевая архитектура. `current.md` содержит только наблюдаемые
факты и ссылки на доказательства. `gaps.md` связывает каждый разрыв с target
и current, назначает следующий наименьший безопасный шаг. `changes.md`
добавляется только после проверенного изменения системы.

## Цикл

1. Зафиксируйте target и фактический current.
2. Сформулируйте и упорядочьте gaps.
3. Создайте задачу в `intent/tasks/` для первого gap.
4. Измените саму систему, а не только документы.
5. Проверьте критерий из gap на фактическом результате.
6. Обновите current, закройте или уточните gap и добавьте запись в changes.

Не объявляйте цикл завершённым без изменения системы и свежей проверки.
