# Gauntlet Loop

Gauntlet Loop применяется к системе, которую нужно приблизить к целевому
состоянию: коду, контентному процессу, исследовательскому контуру или
операционной процедуре.

## Запись состояния

Для одного контура создайте `docs/spec/<scope>/spec.md` по
`templates/spec.md` и `docs/gauntlet/<scope>/` по шаблонам из
`templates/gauntlet-loop/`.

Дерево `docs/spec/<scope>/` — единственный источник желаемого состояния, а
`spec.md` — его вход и карта. Для разработки ПО дерево описывает целевую
архитектуру. `gaps.md` связывает каждый разрыв со spec, наблюдаемым
доказательством в коде, тестах, конфигурации или метриках и следующим
наименьшим безопасным шагом. `changes.md` добавляется только после
проверенного изменения системы.

Отдельный current state не ведите: текущая реализация уже принадлежит коду,
тестам и конфигурации, а её ручной пересказ быстро устаревает.

## Цикл

1. Зафиксируйте spec и доказательства фактического состояния.
2. Сформулируйте и упорядочьте gaps.
3. Создайте задачу в `intent/tasks/` для первого gap.
4. Измените саму систему, а не только документы.
5. Проверьте критерий из gap на фактическом результате.
6. Обновите доказательства, закройте или уточните gap и добавьте запись в
   changes.

Не объявляйте цикл завершённым без изменения системы и свежей проверки.
