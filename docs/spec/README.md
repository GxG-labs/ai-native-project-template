# Spec

Индекс требований и целевой архитектуры.

## Структура

```text
docs/spec/<scope>/
├── spec.md        ← вход, общие требования и карта
└── <module>/      ← детали модуля, когда одного файла недостаточно
```

Начинайте со `spec.md`, затем открывайте только указанные в его карте
модульные материалы. Новый scope создавайте по
[templates/spec.md](../../templates/spec.md).

## Границы

Здесь хранится то, что должно быть правдой. Текущая реализация остаётся в
коде и тестах, а порядок конкретного изменения — в [docs/plan/](../plan/README.md).

Владельцы правил: [PROJECT_STRUCTURE.md](../../PROJECT_STRUCTURE.md) и
[software-change.md](../../ai/workflows/software-change.md).
